2. 如何引入 JavaScript 代码

在 HTML 中引入 JavaScript 代码主要有以下两种方式，具体使用场景和示例如下：

2.1. 内联脚本 (Inline Script)

直接在 HTML 文件中编写 JavaScript 代码

<!DOCTYPE html>
<html>
<head>
  <!-- 在 head 中引入（不推荐影响渲染） -->
  <script>
    console.log('页面加载前执行');
    function init() {
      alert('初始化函数');
    }
  </script>
</head>
<body onload="init()">
  <!-- 在 body 中引入 -->
  <script>
    document.write('页面渲染中插入内容');
  </script>

  <!-- 推荐位置：body 结束前 -->
  <script>
    console.log('DOM加载完成后执行');
  </script>
</body>
</html>

2.2. 外部脚本 (External Script)

通过 src 属性引入独立的 .js 文件

<!DOCTYPE html>
<html>
<head>
  <!-- 标准引入方式 -->
  <script src="js/main.js"></script>

  <!-- 现代属性推荐 -->
  <script src="js/module.js" defer type="module"></script>
</head>
<body>
  <!-- 最佳实践位置 -->
  <script src="js/app.js" async></script>
</body>
</html>

2.3. 模块化引入 (ES) 

<script type="module">
  import { utils } from './js/utils.js';
  console.log(utils.formatDate());
</script>

<!-- 兼容旧浏览器的备用方案 -->
<script nomodule src="js/legacy.js"></script>

2.4. 关键特性对比

特性 内联脚本 外部脚本
代码位置 直接嵌入 HTML 独立 .js 文件
可维护性 适合小型项目/快速测试 适合中大型项目
缓存机制 无法被浏览器缓存 可被缓存提升性能
执行顺序 按文档顺序立即执行 可通过 async/defer 控制
模块化支持 需手动管理 支持 ES6 模块 (type="module")

2.5. defer 和 async的区别

defer 和 async 都是 <script> 标签的属性，用于控制外部脚本的加载和执行方式，以避免阻塞 HTML 解析。它们的核心区别如下：

特性 async defer
下载时机 与 HTML 解析并行下载 与 HTML 解析并行下载
执行时机 下载完成后立即执行（会阻塞 HTML 解析） 等待 HTML 解析完成后执行
执行顺序 无序：谁先下载完谁先执行 有序：按照脚本在文档中出现的顺序执行
适用场景 独立脚本（如统计、广告），不依赖其他脚本或 DOM 需要操作 DOM 或有依赖关系的脚本
DOMContentLoaded 事件 如果脚本在 DOMContentLoaded 之前下载完成并执行，则延迟事件；否则不影响 所有 defer 脚本执行完毕后触发 DOMContentLoaded

2.5.1. 图解流程 

<!-- 普通 script（无属性）：下载+执行都阻塞 HTML 解析 -->
<script src="normal.js"></script>

<!-- async：下载不阻塞，执行阻塞 -->
<script src="async.js" async></script>

<!-- defer：下载不阻塞，执行在 HTML 解析完成后，按顺序执行 -->
<script src="defer.js" defer></script>

2.5.2. 实际例子 

<!DOCTYPE html>
<html>
<head>
    <!-- 假设三个脚本都很大，下载耗时 1~3 秒不等 -->
    <script src="a.js" defer></script>   <!-- 页面解析完后执行 a → b → c -->
    <script src="b.js" defer></script>
    <script src="c.js" defer></script>

    <script src="x.js" async></script>   <!-- 下载完立即执行，可能先于 x、y、z 或乱序 -->
    <script src="y.js" async></script>
    <script src="z.js" async></script>
</head>
<body>
    <!-- 页面内容 -->
</body>
</html>

2.5.3. 总结

  • 没有属性：下载 → 执行 → 阻塞解析 → 继续解析 HTML。
  • async：下载不阻塞，但执行会阻塞，且执行顺序无法保证（适合独立脚本）。
  • defer：下载不阻塞，等待 HTML 完全解析后按顺序执行（适合操作 DOM 或需要保证顺序的脚本）。

2.6. 最佳实践指南

  1. 放置位置建议

    <!-- 推荐：body 闭合标签前 -->
<body>
  <!-- 页面内容 -->
  <script src="js/main.js"></script>
</body>

  2. 性能优化属性

    <!-- 异步加载（不阻塞渲染） -->
<script src="analytics.js" async></script>

<!-- 延迟执行（DOM解析后执行） -->
<script src="ui.js" defer></script>

  3. 安全规范

    <!-- 启用严格内容安全策略 -->
<script src="app.js" integrity="sha384-..."></script>

  4. 现代浏览器支持

    <!-- 模块化开发标准写法 -->
<script type="module" src="main.mjs"></script>

<!-- 传统浏览器备用方案 -->
<script nomodule src="legacy.js"></script>

3. 对象初步

什么是对象？在真实世界中，一个对象就是一个实体。比如对于 human 来说，你这个人就是一个 human 的一个实体对象。映射到在 OOB 的编程语言环境中，对象就是一个和其他实体具有明显边界的，可以和其他实体区分的，聚合在一起的数据和代码。JavaScript对象拥有属性（数据）和 函数（代码）。

3.1. 对象基础

对象是键值对的集合，用于存储复杂数据。

// 创建对象（字面量形式）
let person = {
  name: "Alice",
  age: 28,
  isStudent: false,
  "favorite color": "blue",  // 特殊键名需引号
  greet: function() {
    console.log(`Hello, I'm ${this.name}`);
  }
};

上例中，等号后由 {}限定的部分就是一个对象，person 来代表这个对象。大括号中 name、age、isStudent 为对象的属性，它们有具体的值。"favorite color"这个属性名内部有空格，则必须用单'或双引号"来限定。 greet 也是一个属性，但是这个属性代表了定义为函数的代码。

3.2. 访问属性、函数

  1. 点表示法（Dot Notation）
    语法：对象.键名
    限制：键名必须是有效的标识符（不能以数字开头、不能包含连字符或空格、不能是保留字）。
const obj = {
  name: "Alice",
  age: 25,
  "favorite-color": "blue"
};

console.log(obj.name);  // "Alice"
console.log(obj.age);   // 25
// console.log(obj.favorite-color); // 报错（点号不能解析带连字符的键）

前面提到例子中的 greet 也是属性，所以如下形式访问 greet 时，它的值是函数代码本身。

// 以属性访问
console.log(person.greet); 
/* function() {
    console.log(`Hello, I'm ${this.name}`);
  }
*/

若是调用greet的功能，采用下面的方法：

// 调用方法
person.greet(); // "Hello, I'm Alice"
  1. 方括号表示法（Bracket Notation）
    语法：对象["键名"] 或 对象[变量]
    优势：可以访问任何合法的字符串键（包括特殊字符、数字、表达式）。
const obj = {
  name: "Alice",
  "favorite-color": "blue",
  123: "number key"
};

console.log(obj["favorite-color"]);  // "blue"
console.log(obj[123]);               // "number key"（数字自动转为字符串 "123"）

// 使用变量或表达式
const key = "name";
console.log(obj[key]);               // "Alice"

const prefix = "favorite";
console.log(obj[prefix + "-color"]); // "blue"
  1. 访问 Symbol 键的值
    Symbol 键无法通过点号访问，也不能用普通字符串作为键名，必须使用方括号 + Symbol 变量。
const sym = Symbol("id");
const obj = {
  [sym]: 12345,
  name: "Alice"
};

console.log(obj[sym]);     // 12345
console.log(obj["sym"]);   // undefined（普通字符串键）
  1. 访问不存在的键
    返回 undefined，不会报错。
console.log(obj.unknownKey);  // undefined

4.2.1. 核心定义

4.2.8. 标识符处理机制

  1. 词法分析阶段：引擎解析代码时首先识别标识符
  2. 作用域登记：标识符在对应作用域内登记
  3. 变量提升：var声明会提升到作用域顶部（let/const存在TDZ（Temporal Dead Zone 暂时死区））

4.2.9. 最佳实践总结

  1. 优先使用英文语义化命名
  2. 遵循团队统一命名规范
  3. 避免使用语言保留字
  4. 谨慎使用特殊符号（$、_等）
  5. 保持命名长度适中（3-20字符为佳）
  6. 区分类型前缀（如 arrUsers、isValid）

掌握标识符规范可显著提升代码可读性和维护性，建议结合 ESLint 等工具进行命名规范检查。

字面量是在代码中直接书写的固定值，无需计算即可被 JavaScript 引擎识别。字面量是编写表达式最简洁、最直观的方式。

4.3.2. 基本数据类型字面量

  1. 数字字面量
    JavaScript 中的数字均为双精度浮点数，支持多种表示法。

const int = 42;
const float = 3.14159;
const negative = -273;

// 科学计数法

// 不同进制（ES6+）

const hex = 0xFF;         // 十六进制 → 255

// 特殊数值

// 数字分隔符（ES2021，增强可读性）

  1. 字符串字面量
    可以用单引号 '或双引号 " 包裹。
// 单引号 / 双引号（功能相同）

// 转义字符

// Unicode 转义

// 字符串内单/双引号交替

  1. 布尔字面量、null、undefined
const bool1 = true;

4.3.9. NaN（Not a Number）详解

NaN 是 JavaScript 中的一个特殊数值，全称 Not a Number，意为“不是一个有效的数字”。它属于 number 类型，但表示一个无法被正确解析或运算得到的数值结果。

一、基本定义

typeof NaN;   // "number"
  • NaN 是 number 类型的一个特殊成员。
  • 它表示非法的数字运算结果，比如 0/0、Math.sqrt(-1)、将字符串 "abc" 转换为数字等。
  • 全局属性 NaN 是只读的（不可被重新赋值）。

二、产生 NaN 的常见情况

操作 示例 结果
数学运算中操作数不是数字 "abc" * 2 NaN
0 除以 0 0 / 0 NaN
非数字字符串转换为数字 Number("hello") NaN
对 undefined 进行算术运算 undefined + 1 NaN
负数的平方根（实数） Math.sqrt(-1) NaN
无法解析的 parseInt parseInt("abc") NaN
无效的数学函数参数 Math.log(-1) NaN

console.log("hello" * 3);     // NaN
console.log(Number("abc"));   // NaN
console.log(Math.sqrt(-1));   // NaN

三、NaN 的特殊行为

  1. NaN 不等于自身（最重要特性）
NaN === NaN;   // false
NaN == NaN;    // false

这是 JavaScript 中唯一一个与自身不相等的值。因此不能直接用 === 判断是否为 NaN。

  1. NaN 参与任何运算的结果都是 NaN
NaN + 5;       // NaN
NaN * "hello"; // NaN
Math.sqrt(NaN); // NaN
  1. NaN 与任何值（包括自身）的比较都返回 false
NaN > 0;       // false
NaN < 0;       // false
NaN >= 0;      // false
NaN <= 0;      // false
  1. NaN 是假值（falsy）
    在布尔上下文中，NaN 被视为 false：
if (NaN) {
  // 永远不会执行
}
Boolean(NaN);   // false

四、检测 NaN 的正确方法

方法1：isNaN() 全局函数（有缺陷）

isNaN(NaN);          // true
isNaN("abc");        // true（注意：会先尝试将参数转为数字）
isNaN("123");        // false（转为数字123，不是NaN）
isNaN(undefined);    // true（Number(undefined) → NaN）

缺陷：isNaN 会先将参数强制转换为数字，可能导致意料之外的结果。

方法2：Number.isNaN()（ES6，推荐）

Number.isNaN(NaN);          // true
Number.isNaN("abc");        // false（不会强制转换）
Number.isNaN(undefined);    // false
Number.isNaN(0/0);          // true

优点：只有在参数本身就是 NaN 时才返回 true，不会进行类型转换。

方法3：利用 NaN !== NaN 的特性（兼容老环境）

function isNaNValue(value) {
  return value !== value;
}
isNaNValue(NaN);   // true
isNaNValue(5);     // false

推荐方案

// 安全检测
if (Number.isNaN(someValue)) {
  console.log("这是一个 NaN");
}

五、NaN 与数字运算的传播

console.log(1 + NaN);           // NaN
console.log(Math.pow(2, NaN));  // NaN
console.log(Math.max(1, NaN, 3)); // NaN（只要有NaN参与，结果通常为NaN）

六、常见误区

  • NaN 不是错误，而是一个合法的数值（IEEE 754 标准中的“非数字”信号）。
  • NaN === NaN 为 false，所以不能直接用恒等判断。
  • typeof NaN 是 "number"，不是 "NaN"。
  • 不要用 isNaN() 检测字符串，除非明确想要隐式转换效果。

七、总结

全局变量 NaN（只读）
产生方式 非法数字运算、无法转换的数字字符串等
唯一性 NaN 不等于自身 (NaN !== NaN)
推荐检测方式 Number.isNaN()（ES6）
运算传播 任何包含 NaN 的运算结果都是 NaN

最佳实践：在对数值进行运算或转换后，使用 Number.isNaN() 检查结果，以确保后续逻辑的正确性。

4.4.2. JavaScript 作用域详解

作用域（Scope） 决定了变量、函数和对象在代码中的可访问范围。它是 JavaScript 语言的核心机制之一，理解作用域有助于避免变量冲突、管理内存和调试代码。

一、作用域的基本概念

  • 作用域：变量存在的上下文环境，规定了如何查找变量。
  • 作用域链：嵌套作用域形成的变量查找路径，从内向外逐级查找。
  • 作用域分类：全局作用域、函数作用域、块级作用域（ES6 引入）。

二、作用域的类型

  1. 全局作用域（Global Scope）
  • 在函数和代码块（{}）之外声明的变量属于全局作用域。
  • 浏览器环境中，全局变量会成为 window 对象的属性。
  • 全局变量在任何地方都可访问，但应尽量少用，避免污染命名空间。
let globalVar = "我是全局变量";   // 全局作用域
const PI = 3.14;

function showGlobal() {
  console.log(globalVar);       // 可访问
}

if (true) {
  console.log(globalVar);       // 可访问
}

注意：未使用 var/let/const 声明的变量（非严格模式下）会成为隐式全局变量，应避免。

function errorDemo() {
  mistake = "意外全局变量";      // 没有声明关键字 → 全局变量
}
errorDemo();
console.log(mistake);           // "意外全局变量"（污染全局）
  1. 函数作用域（Function Scope）
  • 用 var 或 function 声明的变量和函数，作用域在整个函数内部，在函数外部无法访问。
  • 函数内部可以访问外部的全局变量和父级函数的变量。
function outer() {
  var funcVar = "函数内部变量";
  
  function inner() {
    var innerVar = "内部";
    console.log(funcVar);   // 可访问 outer 的变量
  }
  
  inner();
  console.log(innerVar);    // ❌ ReferenceError（不在作用域内）
}

outer();
console.log(funcVar);       // ❌ ReferenceError
  1. 块级作用域（Block Scope，ES6+）
  • let 和 const 声明的变量作用域在 {} 代码块内（如 if、for、while、单独的 {}）。
  • 块级作用域可以嵌套，内部可访问外部，反之不行。
if (true) {
  let blockVar = "只在块内有效";
  const PI = 3.14;
  var stillFuncScope = "var 无视块级";   // var 仍是函数作用域或全局
}
console.log(blockVar);        // ❌ ReferenceError
console.log(PI);              // ❌ ReferenceError
console.log(stillFuncScope);  // ✅ 可访问（var 不会受块级限制）

// 单独的块
{
  let x = 10;
  const y = 20;
}
console.log(x); // ❌

for 循环中的块级作用域：

for (let i = 0; i < 3; i++) {
  // i 只在循环体内有效
}
console.log(i);   // ❌ ReferenceError

for (var j = 0; j < 3; j++) {
  // j 在函数作用域或全局
}
console.log(j);   // ✅ 3

三、作用域链（Scope Chain）

当访问一个变量时，JavaScript 引擎会从当前作用域开始向外层作用域逐级查找，直到全局作用域为止。如果最终找不到，则抛出 ReferenceError。

let global = "全局";

function outer() {
  let outerVar = "外层";
  
  function inner() {
    let innerVar = "内层";
    console.log(innerVar);  // 自己作用域找到
    console.log(outerVar);  // 向上找到 outer 作用域
    console.log(global);    // 再向上找到全局
  }
  
  inner();
}

outer();

作用域链的查找顺序：inner 函数作用域 → outer 函数作用域 → 全局作用域。

四、词法作用域（Lexical Scope）

JavaScript 采用的是词法作用域（也叫静态作用域），即函数的作用域在定义时就已经确定，而不是在调用时决定。

let value = "global";

function foo() {
  console.log(value);
}

function bar() {
  let value = "local";
  foo();    // 调用 foo，但 foo 是在全局中定义的，它捕获的是全局的值
}

bar();  // 输出 "global"，而不是 "local"

无论在哪里调用 foo，它都使用定义时所处的变量环境。

五、变量提升（Hoisting）与暂时性死区（TDZ）

  1. var 的变量提升
console.log(a);   // undefined（不是 ReferenceError）
var a = 10;

等效于：

var a;            // 声明提升到顶部
console.log(a);   // undefined
a = 10;
  1. let / const 的暂时性死区（Temporal Dead Zone, TDZ）

let 和 const 也会被提升，但在声明之前访问会报错，这段区域称为 TDZ。

console.log(b);   // ❌ ReferenceError: Cannot access 'b' before initialization
let b = 20;

{
  // TDZ 开始
  console.log(x);  // ❌ ReferenceError
  let x = 5;       // TDZ 结束
}

特点：

  • TDZ 从代码块开始到变量声明语句结束。
  • 使用 typeof 访问 TDZ 中的变量也会报错（不同于未声明的变量）。
  • const 同样有 TDZ，且必须声明时初始化。

六、函数作用域的特殊性

  1. 函数声明提升

函数声明会被整体提升到所在作用域的顶部，因此可以在定义前调用。

sayHello();          // ✅ "Hello"

function sayHello() {
  console.log("Hello");
}
  1. 函数表达式不会被提升
sayHi();             // ❌ TypeError: sayHi is not a function

var sayHi = function() {
  console.log("Hi");
};

七、全局对象与全局作用域

  • 浏览器中，全局 var 变量和函数会成为 window 的属性。
  • let / const 声明的全局变量不会成为 window 的属性，但仍属于全局作用域。
var globalVar = 1;
let globalLet = 2;

console.log(window.globalVar);   // 1
console.log(window.globalLet);   // undefined

八、闭包与作用域（简要介绍）

闭包是指一个函数可以记住并访问它的词法作用域，即使该函数在其词法作用域之外执行。

function createCounter() {
  let count = 0;               // count 被内部函数保留
  return function() {
    count++;
    return count;
  };
}

const counter = createCounter();
console.log(counter());   // 1
console.log(counter());   // 2

外层函数的变量 count 并未因 createCounter 执行完毕而被销毁，因为内部函数还持有对它的引用。这便是闭包对于作用域的延伸。

十、最佳实践

  1. 优先使用 const 和 let，避免 var 带来的作用域污染和提升混乱。
  2. 尽量减少全局变量，使用模块化或立即执行函数（IIFE）隔离作用域。
  3. 理解 TDZ，始终在声明变量后再使用。
  4. 利用块级作用域：在 if、for 中定义的 let/const 不会泄漏到外部。
  5. 避免在循环中用 var 定义函数（会造成所有函数共享同一个变量），改用 let 或闭包。
// 错误示例（用 var）

  setTimeout(() => console.log(i), 100);  // 三个 3
}

// 正确示例（用 let）

  setTimeout(() => console.log(i), 100);  // 0,1,2
}

  1. Base64 编码

Base64是一种编码方法，它使用64个可打印字符来表示二进制数据。这种编码主要用于网络传输，特别是在HTTP协议中传输二进制数据时。由于HTTP协议是基于文本的，因此需要一种方法将二进制数据转换为文本格式。

Base64编码的工作原理是将每三个字节的二进制数据转换为四个字节的文本数据。由于每个字节由8位组成，因此三个字节共有24位。Base64编码将这24位划分为四组，每组6位，因为2的6次方等于64，所以每组6位可以表示一个0到63之间的数字。然后，这些数字被映射到一个包含64个字符的表中，这些字符包括大写字母A-Z、小写字母a-z、数字0-9以及两个额外的符号。这样，原始的二进制数据就被转换成了可打印的文本字符。

如果原始数据不是3的倍数，Base64编码会在数据的末尾添加一个或两个等号（=）作为填充字符。这样做是为了确保编码后的文本数据长度是4的倍数，这是Base64编码的要求。

  .filter(v => v >1)    // [2,3]
  .map(v => v*2)        // [4,6]
  .reduce((a,b) => a+b); // 10

// ES6+ 新特性组合
const matrix = [[1], [2,3]];
matrix.flatMap(arr => arr.map(v => v*2)); // [2,4,6]

4.7.11. 注意事项

  1. 解构不存在的元素会得到undefined
  2. **解构null或undefined**会抛出错误
  3. 默认值只在元素为undefined时生效
  4. 剩余元素必须是最后一个模式
  5. 解构会创建新的变量，不会影响原数组

4.7.12. 类数组对象与转换

类数组对象：具有 length 属性和索引元素，但不是真正的数组（如函数的 arguments、DOM 元素集合 NodeList）。

function sum() {
  // arguments 是类数组
  const args = Array.from(arguments);
  // 或者使用展开运算符
  const args2 = [...arguments];
  return args.reduce((acc, n) => acc + n, 0);
}
console.log(sum(1,2,3));  // 6

// DOM 集合转换
const divs = document.querySelectorAll('div');
const divArray = Array.from(divs);   // 转变为真数组，可使用数组方法

4.7.13. 特殊数组：稀疏数组与多维数组

稀疏数组：含有空槽（empty slot）的数组，应尽量避免使用，因为空槽在某些方法中行为不一致。

const sparse = [1, , 3];  // 索引1为空
console.log(sparse.length);   // 3
console.log(sparse[1]);       // undefined（但属性不存在）
console.log(sparse.hasOwnProperty(1)); // false

// forEach 会跳过空槽，但不会跳过 undefined
sparse.forEach(v => console.log(v));  // 输出 1 和 3（不输出空槽）

多维数组：数组的元素本身也是数组。

const matrix = [
  [1, 2],
  [3, 4]
];
console.log(matrix[0][1]);  // 2

// 遍历二维数组
for (let i = 0; i < matrix.length; i++) {
  for (let j = 0; j < matrix[i].length; j++) {
    console.log(matrix[i][j]);
  }
}

4.7.14. 注意事项与最佳实践

  1. length 属性可写：手动减小 length 会截断数组，增大则填充空槽。

    const arr = [1,2,3];
arr.length = 2;      // arr 变为 [1,2]
arr.length = 5;      // arr 变为 [1,2, 空×3]

  2. delete 与 splice 区别：delete arr[1] 会删除属性但保留空槽（不改变长度），应使用 splice 删除元素。

  3. 避免 for...in 遍历数组：它会遍历所有可枚举属性（包括原型链），推荐使用 for...of、forEach 或传统 for 循环。

  4. 性能注意：

    • push / pop 比 unshift / shift 快（因为不需移动所有元素索引）
    • 大量数据循环时，传统 for 循环比 forEach 略快；但现代引擎差异不大，优先选择语义清晰的写法。

  5. 浅拷贝 vs 深拷贝：

    • 展开运算符 [...arr]、slice()、concat() 都是浅拷贝（只复制一层）
    • 嵌套对象/数组需深拷贝：JSON.parse(JSON.stringify(arr)) 或 structuredClone(arr)

  6. 推荐使用字面量：[] 比 new Array() 更简洁，且避免了构造函数歧义。

  7. 空数组判断：不要用 if (arr === [])，因为它们是不同对象。正确方法：if (arr.length === 0)。

  8. 空位处理差异：map/filter会跳过空位，forEach会保留空位

  9. 性能关键方法：避免在循环中使用concat/slice，优先使用push

  10. 稀疏数组：new Array(3)创建的是[空属性 ×3]，非[undefined ×3]

  11. 推荐实践

  • 优先使用ES6+方法：如 includes 替代 indexOf 检测存在性
  • 避免稀疏数组：显式用 undefined 占位
  • 使用解构交换变量：[a, b] = [b, a]
  1. 常见陷阱

delete arr[1]; // 导致索引1变空位

// 错误判断数组类型

// 错误使用Array构造函数

4.8.4. 空值合并运算符（??）

?? 是 ES2020（ECMAScript 2020）引入的空值合并运算符（Nullish coalescing operator）。它用于提供默认值，但只在左侧表达式的结果为 null 或 undefined 时才会使用右侧的默认值。

一、语法

leftExpr ?? rightExpr
  • 如果 leftExpr 的值是 null 或 undefined，则返回 rightExpr。
  • 否则，返回 leftExpr 本身。

二、与逻辑或（||）的区别

这是理解 ?? 的关键。

运算符 返回右侧的条件 可能产生意外的情况
|| 左侧为假值（false、0、''、NaN、null、undefined） 左侧为 0 或 '' 等有效数据时也会被覆盖
?? 左侧为 null 或 undefined 只在真正“缺失”值时才会覆盖，保留 0、''、false 等有效值 
// 使用 ||
const count = 0 || 100;      // 100（因为 0 是假值）
const name = "" || "匿名";    // "匿名"
const flag = false || true;   // true

// 使用 ??
const count2 = 0 ?? 100;      // 0（0 不是 null/undefined）
const name2 = "" ?? "匿名";    // ""（空字符串是有效值）
const flag2 = false ?? true;   // false

关键结论：当你想要给 null 或 undefined 提供默认值，但需要保留 0、''、false 这些有效值时，?? 是正确选择；而 || 会无差别地把所有假值都替换掉。

三、使用示例

  1. 提供默认值
function greet(user) {
  const name = user?.name ?? "访客";
  console.log(`Hello, ${name}`);
}

greet({ name: "Alice" });   // Hello, Alice
greet({});                  // Hello, 访客
greet({ name: "" });        // Hello, （空字符串被保留）
  1. 处理可能为 null 的配置
const config = {
  timeout: 0,          // 0 是有效的超时值（立即超时）
  retry: null
};

const timeout = config.timeout ?? 3000;   // 0
const retry = config.retry ?? 5;          // 5（因为 retry 是 null）
  1. 与可选链（?.）配合使用
const data = {
  user: {
    // age 不存在
  }
};

const age = data.user?.age ?? 18;   // 18（因为 age 是 undefined）
console.log(age);

四、短路特性

?? 和 || 一样，具有短路求值特性：如果左侧不是 null 或 undefined，右侧表达式不会执行。

function getDefault() {
  console.log("计算默认值");
  return 100;
}

const a = 5 ?? getDefault();   // 不调用 getDefault，直接返回 5
const b = null ?? getDefault(); // 输出 "计算默认值"，返回 100

五、优先级与结合性

?? 的优先级低于大多数运算符，但高于赋值运算符。官方建议在复杂表达式中使用括号明确优先级。

// 正确写法
let result = (a ?? b) || c;

// 错误写法：不能与 && 或 || 直接混用而不加括号
// let x = a ?? b || c;   // 语法错误

规则：?? 在与 && 或 || 同时使用时，必须用括号分组。

六、浏览器支持

  • 现代浏览器：Chrome 80+、Firefox 72+、Safari 13.1+、Edge 80+。
  • Node.js：14.0+。
  • 旧环境可使用 Babel 等工具转译。

七、最佳实践

  1. 需要给缺失值（null/undefined）设默认值时，优先使用 ??，而不是 ||，以免错误覆盖 0、''、false。
  2. 与可选链 ?. 搭配：obj?.prop?.sub ?? defaultValue 是处理深层嵌套对象的安全模式。
  3. 复杂表达式中加括号：(count ?? 0) + 10。
  4. 不要与 && 或 || 无括号混用，会引发语法错误。

八、对比总结

场景 推荐运算符
提供默认值，但保留 0 / '' / false ??
需要过滤所有假值（包括 0 / '' / false） ||
访问深层对象属性并提供默认值 ?. + ??

九、常见陷阱

  • NaN 不会被 ?? 处理：NaN ?? 10 返回 NaN（因为 NaN 不是 null 或 undefined）。
  • 与 || 混淆导致 bug：老代码迁移时要注意区分。
  • 不要用在未声明的变量：会直接抛出 ReferenceError，先用 ?. 或 typeof 检查。

总结：?? 是一个更精确的默认值运算符，它只在值真正缺失（null/undefined）时提供后备值，避免了 || 意外覆盖有效假值的情况。推荐在现代 JavaScript 中用它来代替 || 做默认值设置，除非你明确要过滤所有假值。

4.8.5. 可选链运算符（?.）

?. 是 ES2020（ECMAScript 2020）引入的可选链运算符（Optional Chaining）。它允许安全地访问深层嵌套的对象属性，而无需显式检查中间节点是否存在。如果链中的某个引用是 null 或 undefined，表达式会短路并返回 undefined，而不是抛出错误。

一、语法形式

可选链有三种使用方式：

形式 说明 示例
obj?.prop 访问属性 user?.address?.city
obj?.[expr] 访问动态属性（带方括号） user?.["first name"]
func?.(args) 安全调用函数 callback?.()

二、核心价值

在没有可选链的情况下，访问深层属性需要繁琐的检查：

// 传统写法（容易出错且冗长）
let city;
if (user && user.address && user.address.city) {
  city = user.address.city;
} else {
  city = undefined;
}

// 可选链写法
const city = user?.address?.city;

三、详细使用示例

  1. 访问对象属性
const obj = { a: { b: 42 } };

console.log(obj?.a?.b);   // 42
console.log(obj?.c?.d);   // undefined（不会报错）

// 如果 obj 本身是 null/undefined
const nullObj = null;
console.log(nullObj?.a);  // undefined
  1. 访问数组元素
const arr = [10, 20];

console.log(arr?.[1]);     // 20
console.log(arr?.[100]);   // undefined（数组不越界报错）
  1. 安全调用函数
const obj = {
  greet() { return "Hello"; }
};

console.log(obj.greet?.());     // "Hello"
console.log(obj.bye?.());       // undefined（不会报错）

// 确保变量是函数时才调用
const callback = someCondition ? () => "done" : null;
const result = callback?.();     // 如果 callback 为 null，返回 undefined
  1. 与表达式组合（动态属性）
const key = "age";
const person = { age: 25 };
console.log(person?.[key]);   // 25

四、短路特性

一旦遇到 null 或 undefined，整个可选链表达式立即停止，返回 undefined，后续部分不再计算。

const obj = { a: null };

// obj.a 是 null，所以不会访问 .b，直接返回 undefined
console.log(obj?.a?.b);   // undefined

// 验证右侧未执行
const dangerous = null;
dangerous?.method();      // 不会调用 method，也不报错

五、与 && 运算符的对比

特性 ?.（可选链） &&（逻辑与）
语法简洁度 非常简洁 需要重复属性名
处理 null / undefined 是 是，但也需处理 false、0、'' 等假值（副作用）
短路条件 仅 null / undefined 所有假值
适用动态属性名 obj?.[expr] 方便 需借助 obj && obj[expr]
函数调用 func?.() typeof func === 'function' && func() 
// 使用 &&
const city = user && user.address && user.address.city;

// 使用 ?.
const city = user?.address?.city;

建议：当需要专门的 null / undefined 防护时，优先使用 ?.，因为它意图更明确，且不会意外过滤 0、false、''。

六、与空值合并运算符（??）搭配

可选链和空值合并运算符是绝配：

const city = user?.address?.city ?? "未知城市";
  • 如果 user 或 address 缺失 → undefined → ?? 使用默认值。
  • 如果 city 为空字符串 ""，由于 "" 不是 null/undefined，?? 保留 ""（不用默认值）。

七、注意事项

  1. 不能用于赋值
    可选链的左侧不能作为赋值目标：

    obj?.property = 1;   // SyntaxError

  2. 仅检查 null / undefined
    不会拦截 false、0、NaN、"" 等值。如果需要过滤所有假值，仍需使用 && 或 ||。

  3. 函数调用时
    obj.method?.() 只检查 obj.method 是否存在且可调用。如果 method 是其他类型（如数字），也会短路返回 undefined，不会抛出“not a function”错误。

  4. 短路不删除尾部
    a?.b.c 如果 a 是 null，短路发生在 a?.b，但后续 .c 不会出现错误。实际上可选链只对其左侧的属性访问有效，之后的普通属性访问若发生在 undefined 上仍会报错。但正确写法应始终使用链式可选：

    // 错误（不安全）
a?.b.c   // 若 a 存在但 a.b 不存在，则 a.b.c 仍会报错

// 正确
a?.b?.c

  5. 不支持在赋值模式中解构
    解构赋值无法使用可选链（但可以给默认值）。

八、浏览器与运行环境支持

  • 现代浏览器：Chrome 80+、Firefox 74+、Safari 13.1+、Edge 80+
  • Node.js：14.0+
  • 旧环境可使用 Babel 等编译工具转换

九、最佳实践

  • 优先使用可选链 代替冗余的 && 链式判断。
  • 配合 ?? 为缺失值提供默认值。
  • 避免滥用：对于简单的一级属性，直接访问也不会报错，不需要可选链。
  • 函数调用可选链：当不确定对方是否为函数时使用。

十、总结

目标 推荐方式
安全读取深层属性 obj?.prop?.sub
安全读取数组元素 arr?.[index]
安全调用可能不存在的方法 obj.method?.()
安全读取并提供默认值 obj?.prop ?? defaultValue

可选链运算符显著提高了代码的健壮性和可读性，是现代 JavaScript 中必不可少的工具之一。

4.8.7. 常见错误与陷阱

  2. 避免复杂单行表达式

  4. 利用运算符特性优化代码

4.8.9. 总结要点

  1. 成员访问与函数调用优先级最高
  2. 逻辑与 (&&) 优先级高于逻辑或 (||)
  3. 幂运算 (**) 优先级高于乘除
  4. 赋值运算符优先级最低
  5. 三元运算符右结合：a ? b : c ? d : e → a ? b : (c ? d : e)

建议在复杂表达式中始终使用括号明确运算顺序，避免依赖优先级记忆。可通过浏览器开发者工具的「表达式逐步执行」功能验证运算顺序。

4.10.7. for...of、for...in 和 forEach 的区别详解

这三种都是 JavaScript 中用于遍历数据结构的语法/方法，但它们的设计目标、适用对象、遍历内容以及控制流有显著区别。

一、速览对比表

特性 for...of for...in forEach
遍历对象类型 可迭代对象（Array, String, Map, Set, arguments, NodeList 等） 普通对象（自身及原型链上的可枚举属性） 数组（Array）、Map、Set 等自带 forEach 方法的对象
遍历的内容 集合的值（value） 对象的键名（key，一般为字符串或 Symbol） 数组的元素值（同时可获得索引）
是否支持 break / continue ✅ 支持 ✅ 支持 ❌ 不支持（无法提前终止）
是否支持 return（函数中） ✅ 支持 ✅ 支持 ❌ 不支持（只能跳过当前回调）
是否支持 await ✅ 支持（在异步函数中可 await 表达式） ✅ 支持（但罕见） ⚠️ 需要小心，回调函数不能直接 await；需用 for...of 或 Promise.all
遍历顺序 遵循对象的迭代器定义（通常按插入顺序） 不一定按属性定义顺序（整数键升序，字符串键按添加顺序，但依赖引擎实现） 按数组索引升序（或 Set/Map 的插入顺序）
适用场景 遍历数据集合的值（推荐作为默认选择） 遍历普通对象的属性（尤其是调试、复制属性） 快速对数组每个元素执行函数（无需中断时）

二、详细说明

  1. for...of – 值遍历（推荐）
  • 用于遍历可迭代对象（实现了 [Symbol.iterator] 方法的对象）。
  • 直接取得每个元素的值，语法简洁。
  • 支持 break、continue、return，可在循环中途退出。
  • 支持 await（必须在 async 函数中）。
  • 不能直接遍历普通对象，但可以用 Object.keys() 等转换。
const arr = [10, 20, 30];
for (const val of arr) {
  console.log(val);  // 10, 20, 30
}

const str = "Hi";
for (const ch of str) console.log(ch); // 'H', 'i'

// 支持 break
for (const val of arr) {
  if (val === 20) break;
  console.log(val); // 10
}
  1. for...in – 属性遍历
  • 用于遍历任意对象的可枚举属性，包括自身属性和原型链上的可枚举属性。
  • 遍历的是键名（属性名），而不是值。
  • 对于数组，遍历的是索引（字符串形式），不推荐用于数组（可能包括手动添加的属性）。
  • 需要配合 hasOwnProperty 过滤原型链属性。
  • 支持 break / continue。
const obj = { a: 1, b: 2 };
obj.__proto__.c = 3;  // 原型链属性

for (const key in obj) {
  console.log(key);           // 'a', 'b', 'c'
  if (obj.hasOwnProperty(key)) {
    console.log('own:', key); // 'a', 'b'
  }
}

// 数组示例（不推荐）
const arr = ['x', 'y'];
arr.custom = 'hello';
for (const idx in arr) {
  console.log(idx);  // '0', '1', 'custom'（索引是字符串）
}
  1. forEach – 数组专用迭代方法
  • 是 Array.prototype 上的方法，只能用于数组（以及 Map、Set 等也有类似方法）。
  • 接收一个回调函数，参数依次为 (value, index, array)。
  • 无法使用 break、continue、return 来提前终止（return 只结束当前回调，相当于 continue，但无法停止整个循环）。
  • 不适合异步操作（回调中的异步函数无法等待，循环不会暂停）。
  • 没有返回值（总是 undefined）。
const arr = [1, 2, 3];
arr.forEach((val, idx) => {
  console.log(idx, val);  // 0 1, 1 2, 2 3
});

// 无法跳出
arr.forEach(val => {
  if (val === 2) break;     // ❌ 语法错误
  if (val === 2) return;    // 只跳过当前元素，继续执行
});

三、使用场景建议

场景 推荐方式 原因
遍历数组元素，可能需要中断循环 for...of 支持 break，语法清晰
遍历普通对象的属性 for...in（加 hasOwnProperty）或 Object.keys() + for...of 后者更现代，避免原型链干扰
遍历字符串字符 for...of 正确处理 Unicode 代理对
遍历 Map / Set for...of 原生支持，可同时获取键值
对数组每个元素无中断执行副作用函数 forEach 语义简洁，内建回调参数
异步遍历（如读取文件列表） for...of（配合 await） 可等待每个异步操作完成
需要数组索引和值时，且无需中断 forEach 或 for...of + entries() 都可行

四、异步处理的对比

  • for...of：支持 await，可顺序执行异步任务。
  • forEach：回调内使用 await 不会使循环等待，所有迭代并发启动（但很难控制顺序）。
  • for...in：同样支持 await，但遍历对象属性时很少使用。
// for...of 顺序执行异步
async function process(items) {
  for (const item of items) {
    await doAsync(item);   // 等待完成再继续
  }
}

// forEach 无法等待
items.forEach(async item => {
  await doAsync(item);     // 所有循环并发，不等待
});

五、性能差异

  • 普通 for 循环最快，for...of 和 forEach 相差不大。
  • for...in 最慢（需要遍历原型链），且不应用在数组上。
  • 对于大部分业务代码，性能差异可忽略，优先考虑可读性。

六、总结口诀

  • for...of：拿值，可中断，任何可迭代对象都能用。
  • for...in：拿键，包括原型链，普通对象专用。
  • forEach：只对数组，不能停，回调函数便利多。

实际编码中，建议：

  1. 遍历数组 → 默认 for...of（需要索引时用 entries()）。
  2. 遍历对象属性 → Object.keys(obj).forEach 或 for...of + Object.keys()。
  3. 需要提前结束循环 → 用 for...of 或传统 for。
  4. 简单且无打断需求 → 可用 forEach。

4.11. JavaScript 函数基础详解

4.11.1. 函数的核心概念

函数是一段可重复调用的代码块，用于封装特定功能，具有以下核心特征：

  • 输入：通过参数接收数据
  • 处理：执行内部逻辑
  • 输出：通过返回值提供结果
  • 作用域：拥有独立的作用域环境

  1. 函数表达式（Function Expression）

  1. 箭头函数（Arrow Function，ES6+）
// 简洁语法（无自己的this/arguments）

// 多行语句需用{}和return
const divide = (a, b) => {
  if (b === 0) throw new Error("除数不能为0");
  return a / b;
};
  1. 构造函数定义（不推荐）
const subtract = new Function("a", "b", "return a - b");
console.log(subtract(5, 3)); // 2
