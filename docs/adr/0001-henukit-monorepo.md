# ADR-0001：将 final-review-platform 重构为 HENU Kit 开发 Monorepo

- 状态：Accepted，2026-07-17 修订
- 日期：2026-07-17
- 决策人：HENU Kit 维护团队

## 背景

当前存在三个仓库：

1. `jry21223/HENU-Kit`：公开项目入口、品牌、路线图和社区说明。
2. `jry21223/final-review-platform`：大型学习平台 V2，包含 Next.js、Vue、Go API、Go Worker、PostgreSQL、Redis 及大量业务能力。
3. `jry21223/quizcraft-cn`：独立 QuizCraft 刷题产品，使用 React/Vite、FastAPI 和 PostgreSQL。

跨仓库维护导致账户、API、设计系统、CI 和发布流程容易分叉。实际产品代码需要落在一个开发 Monorepo，但公开的 `HENU-Kit` 仓库仍应保留原名和公开入口职责。

## 决策

- 当前 `final-review-platform` 成为最终 HENU Kit 开发 Monorepo。
- 完成基础迁移后，该仓库改名为 `HENUKitDev`。
- 现有公开仓库 `jry21223/HENU-Kit` 保持原名，不归档、不释放名称，继续承担公开项目入口、公开路线图和社区说明。
- `HENUKitDev` 是实现代码、内部架构、API 契约、测试和部署配置的事实来源。
- `HENU-Kit` 是公开信息的事实来源；需要公开的内容从开发仓经过评审后同步，不并行维护实现代码。
- `quizcraft-cn` 以 subtree 方式导入 `products/quizcraft`，第一阶段保持原技术栈和部署方式。
- 已导入的 `archive/henukit-planning` 仅是公开仓库在导入时的历史快照，不替代公开仓库。
- 当前学习平台代码在迁移期保持原路径和可部署性，逐步收敛为资料库。
- 新平台核心使用 Go 模块化单体，但不把当前混合业务 `services/api` 直接改名为平台核心。
- 子产品独立部署，Monorepo 不等于单体运行时。

## 身份和权限补充决策

- 游客、登录用户和服务账号是不同主体类型。
- 学生、创作者、审核员、运营、管理员和超级管理员是权限角色，一个用户可以拥有多个有作用域的角色。
- Free 与 VIP 是会员档位，不是权限角色。
- 具体能力通过 entitlement 计算，后端不得信任浏览器自报的 role、membership 或 user_id。
- 详细规则以 `docs/architecture/ACCESS_CONTROL.md` 为准。

## 产品边界

- HENU Kit 主站：统一品牌、入口、导航、账户状态和跨产品体验。
- 资料库：只负责资料，不再开发第二套刷题。
- QuizCraft：唯一刷题产品。
- 平台核心：统一账户、角色、会员权益、邮件、通知、事件、统计、服务间认证和 API 契约。

## 方案比较

### 保持多个开发仓库

优点：短期改动最小。  
缺点：共享规范和跨产品变更持续分叉。  
结论：不采用。

### 使用公开 HENU-Kit 仓库替换开发主仓

优点：名称直观。  
缺点：会混合公开入口与私有开发内容，也会破坏现有公开仓库职责。  
结论：不采用。

### 一次性移动全部代码并统一技术栈

优点：表面结构立即整齐。  
缺点：同时改变路径、构建、部署、认证、数据库和运行时，风险不可控。  
结论：不采用。

### HENUKitDev Monorepo + 渐进迁移

优点：公开仓与开发仓职责清晰；可按部署单元迁移并保持回滚。  
缺点：迁移期存在临时目录和兼容层。  
结论：采用。

## 后果

### 正面

- 公开项目入口不会因开发仓重构被覆盖。
- 产品实现和内部技术契约集中到一个开发仓。
- 跨产品变更可在一个 PR 中评审。
- 设计 token、OpenAPI 和测试 fixture 可统一维护。
- CI/CD 可按路径触发并运行全量夜间回归。
- 旧学习平台和 QuizCraft 可继续独立部署。

### 代价

- 仓库体积和 CI 复杂度增加。
- 需要维护公开仓内容同步流程。
- 迁移期同时存在旧路径和目标路径。
- 需要严格 CODEOWNERS、路径过滤和发布单元边界。

## 约束

- 不在导入 PR 中切生产流量。
- 不在目录移动 PR 中同时修改业务语义。
- 不因 Go 统一目标一次性重写 FastAPI。
- 不删除现有支付、资料下载和安全测试。
- 不把业务站数据库合并为平台核心数据库。
- 不通过跨主域共享 Cookie 实现统一登录。
- 不把 VIP 作为审核或管理角色。

## 复审条件

以下情况需要更新 ADR：

- 决定不再使用当前仓库作为开发 Monorepo。
- 决定替换或改名公开 `HENU-Kit` 仓库。
- 采用不同的 QuizCraft 导入或历史保留方式。
- 平台核心从模块化单体改为微服务。
- 子产品部署方式不再独立。
- 身份、角色、会员或数据 Owner 发生重大变化。
