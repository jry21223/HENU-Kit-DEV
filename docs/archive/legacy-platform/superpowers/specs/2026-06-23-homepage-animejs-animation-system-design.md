# 首页 Anime.js 动画系统设计

日期：2026-06-23

## 背景

`final-review-platform` 现在需要明确区分两个 Web 页面角色：

- `/` 是展示首页，用来解释产品能力、建立“中文期末复习资料库”的第一印象，并吸引用户进入工作区或课程资料。
- `/workspace` 是学生工作区，用来查资料、看近期资料、进入课程、查看下载记录和继续学习。

上一轮首页已经实现了资料册式滚动叙事：大尺寸 A4 资料册首屏露角、滚动摆正、文案退场后从中缝打开，左页显示资料目录，右页显示彩色 PDF 课程入口。当前问题不是页面方向错误，而是动画精密度不够，后续区块也偏静态。

本设计把首页重构为 Anime.js 驱动的展示页动画系统。工作区不做同等强度动画，只复用字体、颜色、纸张、资料夹、PDF、印章、标签等视觉语言。

## 目标

1. 让首页动画从“能动”提升到“有统一节奏和精密编排”。
2. 用 Anime.js 统一管理首页展示动画，避免多套动画库争抢同一元素。
3. 保留资料册主叙事：露角、摆正、退文案、翻开、目录显影、课程 PDF 入位。
4. 让后续能力区块像从资料册延展出的附件，而不是普通功能卡片堆叠。
5. 为 `/workspace` 后续视觉统一提供基础语言，但不把首页的大型滚动动画带进工作区。

## 非目标

- 不把 `/workspace` 做成展示页或营销页。
- 不在工作区引入大型滚动动画。
- 不把首页改成 Anime.js 官网的暗色科技风。
- 不承诺真实支付、AI 自动发布、资料命中率等当前产品边界之外的能力。
- 不在本阶段接入真实 API 或重写课程、资料、下载功能页。

## 页面边界

| 路由 | 定位 | 动画策略 |
| --- | --- | --- |
| `/` | 产品展示首页 | Anime.js 高表现力时间线 |
| `/workspace` | 学生资料工作区 | 低动效，高效率，只做状态反馈 |
| `/courses` | 课程资料列表 | 轻量交互，偏工具页 |
| `/materials/[id]` | 资料详情与下载 | 权限和下载状态反馈 |
| `/me/downloads` | 下载记录 | 表格/列表效率优先 |

首页的主 CTA 应指向 `/workspace`，次 CTA 指向 `/courses`。首页可以介绍资料保障、刷题、AI、共创、积分会员和 LangBot，但入口路径仍应清晰地落到工作区和课程资料库。

## 动画原则

### 精密感来源

精密感不等于更多元素同时乱动。首页动画应体现：

- 有主时间线：用户能感到“资料册被定位、打开、归档、展开”。
- 有错峰：目录、PDF、便签、票据、印章按顺序出现。
- 有细节状态：扫描线、索引点、页边高光、标签点亮、印章压下。
- 有克制：动画服务资料库语义，不抢走资料入口。

### 技术原则

- 首页动画统一使用 Anime.js。
- React 负责渲染结构和数据。
- CSS 负责最终静态视觉、布局、材质和 reduced-motion 静态态。
- Anime.js 负责 timeline、stagger、scroll progress 映射和入场编排。
- 同一个元素的同一个 transform 不应被多个系统同时控制。

## 首页动画分镜

### 1. 首屏露角

画面结构：

- 左侧：品牌、标题、说明、搜索框、主 CTA、次 CTA。
- 右下：大尺寸 A4 资料册只露出一角，比例明显大于普通卡片。
- 背景：浅色纸张底，保留学院资料感，不使用深色科技舞台。

动画：

- 页面进入时，文字轻微入场。
- 资料册以轻微倾斜状态稳定停在右下。
- 封面上有低强度材质细节，如标签线、纸张噪点、封面角标。

### 2. 资料册摆正

滚动进入后：

- 资料册旋转归正。
- 资料册从右下移动到视觉中心偏右。
- 资料册尺寸保持大，仍有实体物件存在感。
- 本段不打开封面。

用户感知应是“资料册被放到桌面上”，不是普通元素平移。

### 3. 文案退场

打开之前：

- 左侧标题、说明、搜索框和 CTA 按层级错峰淡出。
- 退场要早于封面打开。
- 退场位移小，避免显得页面跳动。

该段的目标是给开书动作让出视觉焦点。

### 4. 中缝打开

资料册打开：

- 封面沿中缝翻开。
- 中缝出现轻微高光。
- 页边阴影、纸张厚度和内页背景依次显现。
- 打开动作应该有重量感，不能像普通卡片翻转。

完成后形成左右双页：

- 左页：资料目录。
- 右页：彩色课程 PDF 入口。

### 5. 目录扫描

左页动效：

- 一条细扫描线从上到下扫过。
- 目录项逐条显影。
- 每项右侧的“打开”或状态小标签依次点亮。
- 当前目录包括工作区、课程资料、历年真题、实验资料、复习笔记、课程包、我的下载。

语义：资料不是一次性摆出来，而是被系统检索和归档。

### 6. PDF 课程入位

右页动效：

- PDF 小书按顺序错峰入位。
- 每本书从轻微偏移、缩小、低透明度恢复到最终位置。
- 入位时阴影和书脊高光同步显现。
- 课程顺序可沿用当前数据：数据结构、操作系统、计算机网络、软件工程、数据库系统、编译原理。

语义：课程资料正在被整理成可进入的复习包。

### 7. 后续附件展开

资料册段之后，页面继续展示完整产品能力。后续区块不应只是静态卡片：

- 社区便签：像被贴到页面上，带轻微旋转和压贴感。
- 练习纸：批改线、勾选或错题标记逐个显现。
- 积分会员票据：票券虚线、权益标签、课程包标识依次出现。
- LangBot 小纸条：作为辅助咨询入口轻量出现，不成为主 CTA。
- 资料保障：用盖章或校验状态收束，表达稳定供应、轻水印、权限校验和审核边界。

这些区块可以有独立小 timeline，但节奏要继承资料册主线，不要变成互不相关的动效集合。

## 移动端设计

移动端不复刻桌面完整翻页：

- 顶部保留资料册识别和主 CTA。
- 资料册可从轻微倾斜到摆正。
- 目录改为紧凑按钮组。
- PDF 课程入口横向滚动。
- 后续区块单列展示，并使用更短的入场动画。

移动端优先保证阅读、点击目标和性能。复杂翻页、长扫描线、过密错峰动画可以降级。

## Reduced Motion

如果用户开启 `prefers-reduced-motion: reduce`：

- 不执行滚动绑定的长时间线。
- 首页直接展示可读的资料册打开态或静态分段态。
- 目录、课程、后续能力区块全部可见。
- 所有链接、表单和按钮仍可聚焦和访问。

Reduced motion 不是隐藏动画内容，而是跳过运动过程。

## 技术结构建议

建议保留当前 `apps/web/components/home` 的组件边界，但调整动画层：

- `HomePage`：页面组合。
- `home-data.ts`：首页静态数据和入口链接。
- `ArchiveBookReveal`：桌面资料册结构和 Anime.js timeline 容器。
- `MobileArchiveIntro`：移动端简化资料册。
- `home-visuals.module.css`：静态视觉、材质、最终布局和 reduced-motion 静态态。
- `use-home-anime-timeline.ts`：首页主时间线 hook。
- `home-animation-selectors.ts`：集中管理动画 selector 或 data attribute。

动画目标元素应使用稳定 `data-home-anim` 属性，不依赖易变的 Tailwind class 名。

示例命名：

```txt
data-home-anim="hero-copy"
data-home-anim="archive-book"
data-home-anim="archive-cover"
data-home-anim="archive-directory-line"
data-home-anim="course-book"
data-home-anim="community-note"
data-home-anim="practice-mark"
data-home-anim="membership-stamp"
data-home-anim="guarantee-seal"
```

## Anime.js 使用边界

首页可以引入 `animejs`：

```ts
import { animate, createTimeline, stagger } from "animejs";
```

实现前需要以当前安装版本的官方文档为准，特别确认滚动驱动 API、timeline seek、cleanup 和 TypeScript 类型。不按旧版 `anime({...})` 写法做假设。

首页中可以使用 Anime.js 控制：

- opacity
- translate / rotate / scale
- CSS variables
- SVG path / stroke dash
- DOM attributes
- JS 对象形式的 timeline progress

不建议用 Anime.js 控制：

- React 状态本身
- 路由切换
- 表单输入值
- 工作区表格/列表的核心交互状态

## 工作区视觉统一边界

`/workspace` 后续应和首页统一视觉语言，但不统一动画强度。

应统一：

- 字体栈和字号层级。
- 纸张色、墨色、绿色主色、橙色提示色等 token。
- PDF 小书、资料夹标签、印章、轻水印、资料状态标签。
- 面板、按钮、表格、徽标的基础圆角和边框风格。

不应统一：

- 大型滚动叙事。
- 首屏露角物件。
- 复杂翻页。
- 大量错峰装饰动效。

工作区的动画应限于：

- 侧栏收起展开。
- hover/focus 状态。
- loading/skeleton。
- 下载、权限、保存、刷题结果等明确反馈。

## 验收标准

- 首页首屏仍清楚表达“软件学院资料库 / 期末复习资料册”。
- 主 CTA 指向 `/workspace`，次 CTA 指向 `/courses`。
- 桌面端滚动能形成连续叙事：露角、摆正、退文案、翻开、目录扫描、PDF 入位。
- 资料册打开后，左页和右页内容可点击且可聚焦。
- 后续区块有轻量但统一的入场动效。
- 移动端不强行复刻桌面翻页，但保留资料册和课程入口识别。
- Reduced motion 下页面内容完整可读。
- 文案不越过 README 中的支付、AI、权限和资料保障边界。
- `/workspace` 保持工具页属性，不继承首页大型动画。

## 测试建议

保留并扩展现有 Playwright 视觉测试：

- 桌面首屏：资料册只露一角，主 CTA 可见。
- 中段滚动：资料册摆正但未打开。
- 打开段：目录和课程入口可见。
- 后续段：社区、练习、会员、保障区块可见。
- 移动端：简化资料册和横向课程入口可见。
- Reduced motion：资料册内容无需滚动动画即可访问。

构建检查：

- `npm --workspace @final-review/web run lint`
- `npm --workspace @final-review/web run build`

## 实施顺序建议

1. 引入 `animejs` 并建立首页动画 selector 约定。
2. 把首页资料册主动画迁移到 Anime.js 时间线。
3. 增加目录扫描和 PDF 课程入位动效。
4. 增加后续区块轻量入场和印章/批改/票据细节。
5. 完成移动端和 reduced-motion 降级。
6. 扩展 Playwright 视觉测试。
7. 再单独进行 `/workspace` 字体、颜色和基础组件视觉统一。
