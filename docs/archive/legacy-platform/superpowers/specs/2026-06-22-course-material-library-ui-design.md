# 课程资料库 UI 设计语言方案

## 背景

Final Review Platform V2 当前包含 Next.js 学生端和 Vue 3 管理端。第一阶段前端已经具备课程列表、课程详情、资料详情、刷题、学生登录、管理端登录、课程管理和资料管理等基础页面。

本次设计目标不是把平台做成泛教育营销站，也不是把 AI 作为首页主入口，而是建立一套统一、可扩展的 UI 设计语言，让学生端更像可信的课程资料库，让管理端更像高效的资料运营工作台。

## 已确认产品语言

- **课程资料库**：面向本校软件学院学生的课程 PDF 资料入口，核心价值是按课程整理、稳定供应和资料保障。
- **服务院系**：当前只服务本校软件学院，不承诺多院校、全校或全国高校覆盖。
- **课程**：课程资料库的一级入口，学生通过课程进入资料，而不是先筛选院校、学院或专业。
- **资料保障**：前台可感知的服务承诺，包括按课程整理、PDF 稳定下载、持续维护和轻水印。
- **轻水印**：下载资料上的轻量追溯层，不应影响阅读。
- **资料运营工作台**：管理端产品区域，用于维护课程、上传和归档 PDF 资料、查看资料状态。
- **课程社区**：未来围绕课程和资料的讨论、贡献、审核和经验分享层，不做泛社交或独立信息流。
- **资料库原生体验**：主体验围绕找资料、信任资料和下载 PDF；AI 只作为课程/资料上下文中的辅助能力。

## 设计原则

1. **清爽**：浅背景、细边框、低阴影、克制色彩，避免厚重营销风和复杂装饰。
2. **可信**：强调资料来源感、整理状态、最近更新、保障说明和轻水印提示。
3. **轻学术**：保留学习资料和课程语境，避免过度娱乐化。
4. **资料感**：课程卡、PDF 卡、资料类型、更新记录、下载动作必须比 AI 和刷题更突出。
5. **双端一致但不同气质**：学生端偏浏览与转化，管理端偏运营效率。

## 参考方向

采用 shadcn blocks 的区块组织方式：header、card grid、dashboard stats、table、form、sidebar、login block 等组合模式。参考对象是布局语言和组件质感，不是逐页复制。

学生端应借鉴 shadcn 的轻卡片、细边框、明确 CTA 和信息分区。管理端应借鉴 shadcn dashboard 的 sidebar、stat cards、table density 和 form layout。

选定参考区块：

- `dashboard-01`：作为资料运营工作台的主要参考，借鉴 sidebar、顶部栏、统计卡片、图表/概览区和数据表的组合方式。
- `sidebar-07`：作为管理端导航参考，借鉴可折叠侧栏、导航分组和用户区域，不直接复制 React 组件。
- `login-03`：作为学生端和管理端登录页参考，借鉴 muted background、居中窄表单和简洁品牌识别。
- 学生端课程资料库不直接套 dashboard block，应基于 shadcn card、badge、button、input 的视觉语言自建课程卡、PDF 卡和资料保障区块。

## 学生端设计

### 首页

首页采用非全屏 compact hero。第一屏必须同时完成产品定位和资料入口曝光，不能让大 hero 挡住课程入口。

首屏建议结构：

- 顶部导航：品牌、课程资料、资料保障、登录入口。
- Compact hero：标题为“软件学院课程资料库”或同等直白表达。
- 主动作：进入课程资料库。
- 次动作：查看资料保障。
- 首屏下方直接露出课程卡片或最近更新 PDF。

首页不做院校筛选，不做全屏营销 hero，不做 AI chat 首页。

### 课程库

课程库按课程组织。课程卡片应突出：

- 课程名。
- 年级或适用范围。
- PDF 资料数量。
- 资料类型分布，例如讲义、真题、解析、速背。
- 最近更新。
- 资料保障状态，例如已整理、轻水印、持续维护。
- 主按钮：查看资料。

课程库可以保留搜索，但搜索范围是课程、资料标题和关键词，不是院校发现。

### 课程详情

课程详情页是资料转化核心，不是课程介绍页。页面应优先展示：

- 课程标题和资料保障摘要。
- 资料类型筛选。
- PDF 资料列表。
- 最近更新记录。
- 轻水印和下载权限说明。
- 弱入口：课程社区、资料讨论或补充建议。

刷题入口可以保留，但不作为主 CTA。

### 资料详情

资料详情页应帮助用户判断是否下载：

- PDF 标题、类型、文件大小、更新时间。
- 预览内容或摘要。
- 资料保障说明。
- 轻水印提示。
- 主按钮：登录下载或下载资料。
- 错误和权限状态要明确说明，不泄露存储路径。

## 管理端设计

管理端整体定位为资料运营工作台，保留工作台的信息密度，不做学生端营销风。

### 全局框架

- Sidebar：Dashboard、课程管理、资料管理，未来预留内容审核、课程社区、AI 草稿。
- 顶部或内容区显示当前管理员、当前环境和关键状态。
- 主内容区使用 shadcn dashboard 风格的 card、table、form 和 badge。

### Dashboard

Dashboard 应从占位说明升级为运营概览：

- 课程数量。
- 资料数量。
- 最近上传。
- 待维护或待审核状态。
- 资料保障相关提示。

如果后端暂不提供统计接口，第一版可基于现有列表数据在前端计算基础统计。

### 课程管理

课程管理保持创建、归档、列表能力，但视觉上统一：

- 表单分区更清晰。
- 表格状态使用 badge。
- 课程和资料数量可作为后续字段预留。

### 资料管理

资料管理是管理端核心：

- 上传表单突出 PDF 文件、课程、资料类型、权限、预览内容。
- 上传后列表显示文件名、类型、权限、状态和归档动作。
- 状态文案与学生端资料保障保持一致。

## AI 与课程社区边界

AI 不作为首页主入口。后续可以在课程详情或资料详情中作为“资料摘要”“问这份资料”“重点提取”等上下文能力出现。

课程社区不作为第一版主导航。第一版 UI 只预留可扩展位置，例如资料讨论、补充建议、更新记录和贡献者提示。

## 依赖与技术边界

学生端是 Next.js + Tailwind，可以引入 shadcn 风格的本地 UI 组件组织方式，并允许增加轻量基础依赖，例如 `lucide-react`。是否引入 `clsx`、`class-variance-authority`、`tailwind-merge` 等 class helper，应以后续实现需要为准，避免为样式系统过度铺垫。

管理端是 Vue 3 + Element Plus。管理端不直接使用 shadcn React 组件，应保留 Element Plus，并通过全局 CSS、布局结构、颜色、边框、圆角、badge 和表格密度统一到同一套设计语言。

本次设计不要求重写后端，不接真实支付，不引入真实密钥，不承诺 AI 精准总结或资料全覆盖。

## 验收标准

- 学生端第一屏能直接看出这是软件学院课程资料库，并且第一屏能看到课程或资料入口。
- 学生端主 CTA 指向查看资料或下载资料，不以刷题或 AI 作为主动作。
- 课程卡和资料卡能表达资料数量、类型、更新和保障感。
- 管理端保持工作台效率，表格、表单和状态展示更清晰。
- 双端在颜色、边框、圆角、按钮、badge、卡片风格上保持一致。
- 页面文案不出现过度承诺，例如必考命中、老师原版、AI 精准总结、全国高校覆盖。
- `npm run lint` 和 `npm test` 在实现后必须通过。
