# HENU Kit 产品边界

> 状态：迁移基线 v1.0  
> 适用仓库：当前 `final-review-platform`，迁移完成后改名为 `HENU-Kit`

HENU Kit 是统一校园工具系统，不是简单的网站导航集合。统一指产品身份、账户、导航、状态语义、API 契约和设计规范统一；不要求所有子产品使用同一个前端框架或同一个部署进程。

## 1. 面向用户的一级结构

```text
HENU Kit
├── 美食榜单
├── 工具箱
├── 学习
│   ├── 资料库
│   ├── 刷题
│   └── 接毕设（二期）
└── 平台核心（隐藏基础设施）
    ├── 统一账户
    ├── 邮件
    ├── 通知分发
    ├── 用户统计
    ├── 服务间认证
    └── API 规范
```

首页不得把“账号中心”“邮件平台”“通知中心”“数据中台”包装成用户一级入口。用户只看到完成任务所需的入口。

## 2. 主站

### 唯一职责

- HENU Kit 品牌与产品归属。
- 三个一级入口。
- 全局导航、账户入口和产品状态。
- 工具目录、维护状态、更新时间与公告。
- 学习聚合入口。
- 非官方声明。

### 明确不做

- 不复制资料详情或文件存储。
- 不实现题库、作答、错题或排行榜。
- 不自行实现第二套账户和邮件系统。
- 不复制所有业务后台。
- 不把外链列表当作完整产品体验；进入子产品后仍需维持统一导航、账户和视觉。

## 3. 资料库

### 当前与目标地址

- 当前：`study.superhuazai.me`
- 目标别名：`study.henukit.cn`

### 唯一职责

- 学校、学院、专业、课程组织。
- 资料检索和筛选。
- 资料详情。
- 资料预览与下载。
- 投稿、审核和纠错。
- 下载审计与必要的资料管理后台。

### 刷题边界

资料库只展示资料库。它不再开发、运营或宣传第二套刷题产品。

允许存在的刷题相关行为只有：

1. 课程页显示“去刷题”。
2. 通过课程映射把用户跳转到 QuizCraft 对应题库。
3. 返回资料库时保留来源页面上下文。

资料库不得继续新增：

- 自有题库和题目编辑。
- 自有作答记录。
- 自有错题本。
- 自有练习进度。
- 自有刷题排行榜。
- 自有薄弱点分析。

### 首页体验

保留“打开资料册”的创意，但改为轻量一次性动画：

- 时长建议 `600–900ms`。
- 核心动画层控制在 `3–6` 个。
- 只使用 `transform` 和 `opacity`。
- 搜索框、标题和主要按钮首帧可操作。
- 移动端默认静态或简单淡入。
- `prefers-reduced-motion: reduce` 完全关闭非必要动画。
- 不保留长距离 sticky、连续翻页、多层视差和随滚动持续计算。

## 4. QuizCraft 刷题产品

### 当前与目标地址

- 当前：`superhuazai.me` / `superhuazai.me/practice`
- 目标别名：`quiz.henukit.cn`

### 唯一职责

- 题库和题目。
- 随机、章节、难题等练习模式。
- 作答判分。
- 错题。
- 练习进度。
- 排行榜。
- 题目反馈。
- 题库工坊、导入、校验、编辑和管理。
- 题目解析生成流程。

### 技术边界

第一阶段保留 React/Vite + FastAPI + PostgreSQL。新平台核心使用 Go 不构成一次性重写 QuizCraft 的理由。

迁移采用：

- 统一账户适配。
- 服务间认证。
- OpenAPI 兼容层。
- 读取接口优先迁移。
- 作答写接口最后迁移。
- 影子流量、双读/双算和功能开关。
- 任何生产切换必须可立即回到 FastAPI。

## 5. 平台核心

### 唯一职责

- 不可猜测的统一 `user_id`。
- 学生邮箱身份与验证状态。
- 登录会话和会话撤销。
- 跨主域 Authorization Code Flow。
- 邮件发送、优先级和投递状态。
- 站内通知和通知偏好。
- 标准业务事件和 Outbox。
- 用户数量与活跃用户统计。
- 服务间认证和密钥轮换。
- OpenAPI、统一错误码、请求 ID 和审计。
- Health、Readiness 和基础可观测性。

### 明确不保存

- 题目和答案。
- 作答、错题和练习进度。
- 课程资料文件。
- 餐厅、榜单和投票。
- 毕设项目正文。
- 工具目录正文。

### 数据访问规则

- 业务模块通过平台 API 使用平台能力。
- 业务模块不得读取平台核心数据库。
- 邮箱不得作为跨服务长期关联键。
- 每类业务数据只能有一个 Owner。

## 6. 原学习平台遗留能力

当前 `services/api` 和相关前端仍包含账号、通知、积分、刷题、Wiki、Blog、论坛、动态、AI、支付和会员。迁移期间不得直接删除。

| 能力 | 迁移期处理 | 目标方向 |
|---|---|---|
| 课程、资料、下载、投稿、审核、纠错 | 保留并继续维护 | 资料库 Owner |
| 账号、验证码、会话 | 保留兼容入口，冻结新增协议 | 迁移到平台核心 |
| 通知 | 保留现有站内通知，补事件适配 | 迁移到平台核心 |
| 刷题、作答、错题、排行榜 | 隐藏新增入口，冻结功能开发 | 由 QuizCraft 替代 |
| 积分 | 暂不删除，先确认投稿和付费依赖 | 团队拍板后迁移或冻结 |
| Wiki | 只保留服务资料整理和共建的部分 | 资料库附属能力或冻结 |
| Blog、论坛、动态 | 前台隐藏/冻结，保留数据与后台只读 | 验证使用情况后处理 |
| AI | 仅保留资料处理或题库生产相关工作流 | 按业务 Owner 拆分 |
| 支付、会员 | 不在平台重构期扩展 | 独立商业决策后处理 |

每项最终删除前必须满足：线上使用量已确认、数据已备份、依赖已解除、替代入口已上线、回滚窗口已结束。

## 7. 统一品牌规则

- 主色名称：**Kit 墨绿**，`#0C6B45`。
- 不得称为“河大绿”“河南大学官方标准色”或学校官方 VI。
- 页面、README、登录、支付和宣传材料必须明确：

> HENU Kit 是由河南大学学生自主发起并维护的校园工具项目，非河南大学官方产品，不代表学校官方立场。

空间有限时使用：

> 学生自主运营 · 非河南大学官方项目

## 8. 域名与跳转

目标域名：

| 能力 | 目标域名 |
|---|---|
| 主站 | `henukit.cn` |
| 统一账户 | `account.superhuazai.me`（当前备案域名） |
| 资料库 | `study.henukit.cn` |
| 刷题 | `quiz.henukit.cn` |
| 邮件发件域 | `notify.henukit.cn` |

旧域名在迁移完成前保留兼容入口。不能通过跨主域共享 Cookie 实现统一登录；业务站使用授权码交换身份，并建立自己的 HttpOnly、Secure 会话。

## 9. 新功能评审问题

任何新功能进入开发前必须回答：

1. 它解决哪个用户的什么任务？
2. 唯一数据 Owner 是谁？
3. 为什么不能由现有模块承担？
4. 是否会复制资料库或 QuizCraft 的既有能力？
5. 失败、权限不足和回滚路径是什么？
6. 如何用真实使用数据验证价值？

无法回答以上问题的功能不得进入开发。
