# 统一管理后台产品需求 V1.0

## 1. 产品目标

统一管理后台面向管理员、运营、审核员和受限业务维护者，提供一个可执行的工作台，而不是只展示数字的大屏。

后台必须支持三类任务：

1. **发现问题**：用户、通知采集、邮件投递、反馈、美食榜单、服务运行异常。
2. **处理问题**：审核、分配、重试、调档、冻结、撤销、纠错和关闭。
3. **追溯问题**：查看来源、版本、请求链路、操作日志和处理历史。

## 2. 用户角色

| 角色 | 主要能力 | 限制 |
|---|---|---|
| Operator | 平台反馈、通知运营、邮件受控查看、统一待办 | 无角色授予、服务密钥和全局配置权限 |
| Reviewer | 指定课程、题库、学院或美食范围内审核 | 受 scope 限制，不可越权处理 |
| Admin | 用户、业务配置、内容和运营管理 | 不自动获得 Super Admin 安全操作 |
| Super Admin | 服务凭据、全局权限、重大安全操作 | 高风险操作要求近期验证和审计 |

VIP 是会员权益，不是后台角色。

## 3. 信息架构

```text
总览
用户与受众
校园通知
邮件投递
反馈中心
美食榜单
资料库运营
刷题运营
系统运行
审计与安全
平台设置
```

## 4. 总览

### 4.1 全局筛选

- 时间范围：今日、7 日、30 日、自定义。
- 组织范围：全校、校区、学院。
- 产品范围：platform、notice、study、quiz、food。
- 环境：production、staging。
- 数据时间：每个数据块显示 `as_of`。

### 4.2 六张首屏卡片

1. 用户：已验证用户、今日新增、DAU、学院资料完成率。
2. 校园通知：今日采集、待审核、失败来源、待分发。
3. 邮件：Critical 接受率、排队数、最老任务、死信。
4. 反馈：平台反馈、题目反馈、超时数、今日解决。
5. 美食：待审核投稿、升档候选、降档候选、异常票。
6. 系统：正常/降级服务、Outbox 积压、Worker 异常。

### 4.3 今日待办

每条待办包含严重度、来源、摘要、资源引用、创建时间、到期时间和可点击处理路径。

首发必须覆盖：

- Critical 邮件排队超时或死信；
- 通知源连续失败或页面结构变化；
- 平台反馈与题目反馈超时；
- 美食投稿超时；
- 美食调档候选和异常校准票；
- 服务 Readiness 失败；
- 聚合数据过期。

### 4.4 图表

- 用户新增与 DAU 趋势；
- 学院用户数与资料完成率；
- 通知采集 → 审核 → 分发漏斗；
- 三类邮件状态趋势；
- 平台反馈、题目反馈、美食投稿趋势；
- 五档美食分布与调档候选。

## 5. 用户与受众

### 5.1 用户列表

字段：

- 脱敏邮箱；
- 显示名；
- 账号状态；
- 邮箱验证状态；
- 学院、专业、年级；
- 学业档案来源；
- 会员档位；
- 角色摘要；
- 最近活跃；
- 创建时间。

筛选：状态、学院、专业、年级、会员、角色、资料是否完整、订阅状态。

操作：查看详情、冻结/解冻、撤销 Session、修正学业档案、管理作用域角色。

### 5.2 用户详情

- 账号基本信息；
- 学业档案；
- 角色、Scope、会员与 Entitlement；
- 通知订阅；
- 最近 Session；
- 最近邮件投递；
- 平台反馈；
- 审计记录。

完整邮箱只有具备 `users.email.reveal` 权限时显示，并写审计。

### 5.3 受众统计

- 各学院、专业、年级人数；
- 学业档案完成率；
- 未选择学院和学院/专业不匹配人数；
- 各组织通知订阅率；
- 退订、无效邮箱和抑制名单人数。

## 6. 校园通知

### 6.1 通知来源

字段：来源名称、所属组织、状态、抓取频率、最后成功、最后发现、连续失败、HTTP 状态、解析器版本、页面结构变化、今日新增/更新、待审核。

操作：创建、修改、暂停、恢复、立即抓取、测试解析、查看失败历史。

### 6.2 通知内容

字段：标题、来源、组织、原发布时间、首次抓取、当前版本、重要程度、推荐受众、最终受众、审核状态、分发状态。

详情：原链接、正文、附件、历史版本、差异、摘要、受众和分发记录。

状态：`review_pending`、`approved`、`rejected`、`published`、`expired`。

### 6.3 分发任务

- 目标用户数；
- 匹配学院人数；
- 主动订阅人数；
- 因退订/无效邮箱/重复跳过；
- 站内通知与邮件任务；
- queued、accepted、deferred、bounced、failed；
- 开始、结束和取消状态。

## 7. 邮件投递

### 7.1 队列分类

- `critical`：验证码、账号安全；
- `transactional`：投稿、审核、积分等；
- `digest`：校园通知摘要。

### 7.2 邮件概览

- queued、sending、accepted、delivered、deferred、bounced、failed、retry_due、dead_letter；
- P50/P95 排队时间；
- 最老任务；
- 每分钟发送量；
- 各收件域接受率、退信率；
- SPF、DKIM、DMARC、PTR；
- 抑制名单和退订率。

### 7.3 投递详情

模板、类别、脱敏收件人、收件域、发信域/IP、状态、尝试次数、下次重试、SMTP 响应分类、request_id 和时间线。

操作：安全重试、加入/移出抑制名单、死信重放。不得显示验证码正文或完整第三方错误正文。

## 8. 反馈中心

### 8.1 统一待办

统一队列只保存摘要、优先级、负责人、SLA、来源服务和资源 ID，不复制原始业务正文。

### 8.2 平台反馈

范围：账号、登录、邮件、通知、学院信息、资料库、页面、权限、性能、系统故障和建议。

详情：用户、学院、内容、页面 URL、设备、request_id、关联邮件/通知、优先级、状态、负责人、首次响应、解决时间和处理记录。

状态：`new`、`triaged`、`in_progress`、`waiting_user`、`resolved`、`closed`、`rejected`。

### 8.3 QuizCraft 题目反馈

范围：答案错误、答案争议、题干错误、条件缺失、选项错误、解析错误、图片/公式异常、重复题、标签错误。

必须显示反馈发生时的题目、选项、答案、解析和用户答案快照。

兼容状态：`pending`、`resolved`、`archived`。只有 JSON 题库、PostgreSQL 和线上 API 均验证完成后才可 resolved。

## 9. 美食榜单

### 9.1 固定语义

五档名称由配置表定义，首发显示：夯、人上人、顶级、NPC、拉完了。具体顺序由 `sort_order` 控制，禁止前端硬编码。

投稿人选择建议初始档位并说明理由。社区只判断当前档位：

- `underrated`：被低估了；
- `about_right`：差不多；
- `overrated`：被高估了。

### 9.2 投稿审核

字段：美食名称、店铺/档口、校区、位置、图片、描述、建议档位、理由、投稿人、重复风险、状态、等待时长。

操作：通过、驳回、要求补充、合并到现有条目。

### 9.3 榜单条目

字段：初始档位、当前档位、当前轮次、三类票数/比例、有效参与人数、共识状态、调档建议、异常票、冷却期、最近调档。

### 9.4 校准轮次

每次调档后关闭旧轮次并创建新轮次。一个用户在一个轮次内只有一个有效判断，可在轮次开放期间修改。

候选状态：

- `insufficient_votes`；
- `stable`；
- `promote_candidate`；
- `demote_candidate`；
- `contested`；
- `cooldown`；
- `blocked_by_risk`。

首发由系统给出建议，管理员确认后最多升/降一档。

### 9.5 异常校准票

识别：短时集中投票、同 IP/设备多账号、新账号立即投票、同组织异常集中、反复修改和突增。

票状态：`valid`、`suspected`、`invalidated`、`restored`。任何作废和恢复必须审计。

## 10. 资料库运营

复用现有课程、资料、下载、审核和纠错能力，逐步换为统一导航与 shadcn-vue 页面。

首发保留：课程、资料、资料审核、下载趋势、热门资料、课程供给缺口和资料举报。

## 11. 刷题运营

- 题库总数和启用状态；
- 开始练习、提交作答、活跃用户；
- 热门题库；
- 题目反馈；
- JSON/PostgreSQL 一致性；
- 后续 Go Adapter 影子差异。

## 12. 系统运行

- Portal、Platform Core、Study、Quiz、Food、Notice、Mail 服务状态；
- PostgreSQL、Redis、Worker；
- API 5xx、P95；
- Outbox、Stream Pending、DLQ；
- Migration 版本；
- Commit SHA 和部署时间；
- 数据聚合任务新鲜度。

## 13. 审计与安全

记录：角色变化、用户冻结、Session 撤销、完整邮箱查看、通知审核/分发、来源配置、邮件重试/死信、美食审核/调档/票作废、题目反馈处理、批量导出和服务密钥操作。

审计至少包含 actor、action、resource、before/after 摘要、request_id、IP 前缀和 created_at。

## 14. 非首发范围

- 自定义报表与拖拽大屏；
- AI 自动审核和自动调档；
- 文字评论与社交关系；
- 商家认领；
- 营销邮件；
- 跨学校多租户；
- 无人工确认的大规模批量高风险操作。
